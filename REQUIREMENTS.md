# Requirements & Dependencies

This document explains how dependencies are managed in AQI Predictor. We use **pyproject.toml** as the single source of truth with optional feature groups.

---

## 📋 Quick Reference

| Use Case | Command | Files |
|----------|---------|-------|
| **Run API + Dashboard** | `pip install -e .` | Core dependencies from pyproject.toml |
| **Development** | `pip install -e ".[dev]"` | Core + dev tools (Black, pytest, mypy) |
| **Testing** | `pip install -e ".[test]"` | Core + pytest, coverage tools |
| **Hopsworks Integration** | `pip install -e ".[feature-store]"` | Core + hopsworks (separate venv) |
| **Training Pipeline** | `pip install -e ".[training]"` | Core + sklearn, lightgbm, optuna |
| **All Features** | `pip install -e ".[dev,feature-store,training]"` | Everything (⚠️ conflicts possible) |

## 🏗️ Architecture

### Single Source of Truth: `pyproject.toml`

All dependencies are defined in **pyproject.toml** with semantic versioning (exact pins):

```toml
[project]
dependencies = [
    # Core dependencies for API + Dashboard
    "fastapi==0.141.1",
    "streamlit==1.61.1",
    "pandas==2.3.3",
    # ... more
]

[project.optional-dependencies]
feature-store = [...]  # Hopsworks integration
training = [...]       # ML training tools
dev = [...]           # Development tools
test = [...]          # Testing frameworks
docs = [...]          # Documentation
```

### Why `pyproject.toml`?

- ✅ **Single source of truth** - All dependencies in one place
- ✅ **Modern Python standard** (PEP 517/518)
- ✅ **Optional groups** - Install only what you need
- ✅ **Better IDE support** - Tools understand pyproject.toml
- ✅ **Easy to maintain** - No duplicate version specs across files
- ✅ **Works with pip-tools** - Can generate lock files if needed

## 📦 Dependency Groups

### 1. Core Dependencies (Always Installed)

```bash
pip install -e .
```

**What's included:**
- Data processing: pandas, numpy, scikit-learn
- ML models: lightgbm, keras
- Web: FastAPI, Streamlit, Plotly
- Utils: requests, python-dotenv, pyarrow
- Monitoring: prometheus-client

**Use when:** Running API, dashboard, or inference

### 2. Development Tools

```bash
pip install -e ".[dev]"
```

**What's included:**
- Code formatting: Black
- Linting: flake8, ruff
- Type checking: MyPy
- Pre-commit hooks: pre-commit

**Use when:** Contributing code, local development

### 3. Testing

```bash
pip install -e ".[test]"
```

**What's included:**
- Test framework: pytest, pytest-cov
- Async testing: pytest-asyncio
- Fixtures: pytest-mock
- Utilities: freezegun, responses, httpx

**Use when:** Running test suite

### 4. Feature Store (Hopsworks)

```bash
pip install -e ".[feature-store]"
```

**What's included:**
- Hopsworks SDK (>=5.0.4)
- Kafka client (confluent-kafka)
- Avro serialization (fastavro)

**⚠️ IMPORTANT:** Hopsworks has hard dependency conflicts with keras/Streamlit:
- hopsworks pins: `protobuf<5.0.0,>=4.25.4`
- keras requires: `protobuf>=5.26.1`
- Result: **Cannot install together in same venv**

**Use when:** Feature engineering, historical backfill

**Installation (Linux/macOS with gcc):**
```bash
# Create separate venv for feature store
python -m venv .venv-hopsworks
source .venv-hopsworks/bin/activate
pip install -e ".[feature-store]"
python scripts/historical_backfill.py
```

**Installation (Windows, no C compiler):**
```bash
py -3.12 -m venv .venv-hopsworks
.venv-hopsworks\Scripts\activate
pip install "hopsworks==5.0.4" --no-deps
pip install "pandas<2.4.0" "numpy<2.5.0" \
    "protobuf<5.0.0,>=4.25.4" confluent-kafka
python scripts/historical_backfill.py
```

### 5. Training Pipeline

```bash
pip install -e ".[training]"
```

**What's included:**
- ML libraries: scikit-learn, lightgbm, optuna
- Note: Does NOT include Hopsworks

**Use when:** Running daily training pipeline, hyperparameter tuning

### 6. Documentation

```bash
pip install -e ".[docs]"
```

**What's included:**
- Sphinx documentation tools
- Read-the-Docs theme

**Use when:** Building HTML docs from source

## 📄 Legacy Requirements Files (Reference Only)

These files are **kept for reference and CI/CD automation** but are NOT recommended for manual installation:

### `requirements.txt` (Deprecated)
- **Purpose:** Legacy core dependencies list
- **Why kept:** CI/CD workflows, Docker builds reference it
- **Status:** Mirrors pyproject.toml [project.dependencies]
- **Generated by:** `pip freeze` (Issue #44 - dependency pinning)

### `requirements-feature-store.txt` (Separate venv ONLY)
- **Purpose:** Hopsworks feature-store pipeline environment
- **Why separate:** Hard conflicts with keras/protobuf versions
- **Status:** MUST stay in separate venv, never merge into main
- **Generated by:** Manual maintenance + documentation
- **Used by:** `.github/workflows/feature_pipeline.yml`

### `requirements-training.txt` (Separate venv ONLY)
- **Purpose:** Daily training pipeline environment
- **Why separate:** Depends on Hopsworks (for feature store access) + training libraries
- **Status:** Includes requirements-feature-store.txt via `-r` directive
- **Used by:** `.github/workflows/training_pipeline.yml`

### `requirements-test.txt` (Deprecated)
- **Purpose:** Legacy test dependencies list
- **Status:** Mirrors pyproject.toml [project.optional-dependencies.test]
- **Recommendation:** Use `pip install -e ".[test]"` instead

## 🔄 Dependency Management Workflow

### For End Users

```bash
# Installation
git clone https://github.com/AyyanStorm/aqi-predictor.git
cd aqi-predictor
pip install -e .          # Core only
pip install -e ".[dev]"   # Add dev tools
pytest tests/             # Run tests
```

### For Developers

```bash
# Setup development environment
pip install -e ".[dev,test]"
pre-commit install
black src/ app/ tests/
mypy src/ app/
pytest tests/ --cov
```

### For Feature Store / Training

```bash
# Create separate venv for Hopsworks-dependent work
python -m venv .venv-hopsworks
source .venv-hopsworks/bin/activate
pip install -e ".[feature-store]"
python scripts/historical_backfill.py

# Separate venv for training (includes hopsworks)
python -m venv .venv-training
source .venv-training/bin/activate
pip install -e ".[training]"  # Includes hopsworks (feature store access)
python -m src.training.train --model lgbm --register
```

### For CI/CD Pipelines

**GitHub Actions lint.yml:**
```yaml
pip install -e ".[dev,test]"
black --check src/ app/ tests/
mypy src/ app/
pytest tests/
```

**GitHub Actions feature_pipeline.yml:**
```yaml
pip install -r requirements-feature-store.txt
python scripts/hourly_ingest.py
```

**GitHub Actions training_pipeline.yml:**
```yaml
pip install -r requirements-training.txt
python -m src.training.train
```

## 🚨 Dependency Conflicts & Solutions

### Known Conflict: Hopsworks ↔ Keras

**Problem:**
```
hopsworks requires: protobuf<5.0.0,>=4.25.4
keras requires: protobuf>=5.26.1
Result: pip cannot satisfy both → installation fails
```

**Solution: Separate Virtual Environments**

```bash
# Main venv: API + Dashboard (with keras)
python -m venv .venv
source .venv/bin/activate
pip install -e .

# Feature Store venv: Hopsworks only
python -m venv .venv-hopsworks
source .venv-hopsworks/bin/activate
pip install -e ".[feature-store]"
```

**Why this works:**
- Each venv is isolated
- `hourly_ingest.py` runs in `.venv-hopsworks`
- `streamlit_app.py` runs in `.venv`
- No conflicts because they never run together

## ❓ FAQ

**Q: Which file should I use?**
A: Use `pip install -e .` (and optional groups). The .txt files are for reference/CI only.

**Q: Why keep separate .txt files?**
A: For CI/CD automation and explicit documentation of conflicts (hopsworks).

**Q: Can I install everything together?**
A: No - hopsworks + keras cannot coexist. Use separate venvs for feature-store work.

**Q: How do I update dependencies?**
A: Edit pyproject.toml, then regenerate .txt files with:
```bash
pip install pip-tools
pip-compile pyproject.toml -o requirements.txt
```

**Q: Is pip-tools used?**
A: No - we manually pin exact versions in pyproject.toml. pip-tools optional for future lock files.
